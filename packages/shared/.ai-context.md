# AI Context - Shared Package

## Package Purpose
Common types, utilities, and constants shared across all apps and packages.

## Current Structure
```
src/
├── types/         # TypeScript interfaces and types
├── utils/         # Helper functions
├── constants/     # App constants
├── services/      # API service classes
└── index.ts       # Main exports
```

## Key Types
- **User** - User profile structure
- **Transaction** - Payment/transaction data
- **CoinPackage** - Coin package definitions
- **ApiResponse** - Standardized API responses
- **Toast/ToastOptions** - Notification system
- **Article** - Blog/content structure

## Utilities
- API helpers
- Validation functions
- Date/time utilities
- Format helpers
- Common calculations

## Export Pattern
```typescript
// Types
export type { User, Transaction, ApiResponse }

// Utilities
export { formatDate, validateEmail, debounce }

// Constants
export { API_ENDPOINTS, ERROR_MESSAGES }
```

## Design Principles
- **Framework Agnostic** - Works with any frontend framework
- **Type Safety** - Full TypeScript coverage
- **Reusability** - Common patterns extracted
- **Consistency** - Standardized interfaces

## Dependencies
- Minimal external dependencies
- Peer dependencies for optional features (Stripe, Supabase)
- Tree-shakeable exports

## Usage Patterns
```typescript
// In apps
import { User, formatDate } from '@monorepo/shared'
import type { ApiResponse } from '@monorepo/shared'

// Re-export pattern in app types
export type { User, ApiResponse } from '@monorepo/shared'
```

## When Adding to Shared
1. **Types**: Add if used in 2+ places
2. **Utils**: Add if logic is complex or reusable
3. **Constants**: Add if values need consistency
4. **Services**: Add if API patterns repeat

## Versioning
- Semantic versioning for breaking changes
- Workspace versioning for internal deps
- Consider backward compatibility

## Testing
- Unit tests for utilities
- Type tests for interfaces
- Integration tests for services
