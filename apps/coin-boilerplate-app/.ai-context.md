# AI Context - Coin Boilerplate App

## App Purpose
Digital coin purchase platform with OAuth authentication and Stripe payments.

## Current Structure
```
components/
├── layout/     # (empty - could add layout components)
├── forms/      # (empty - could add form components)
└── ui/         # ErrorBoundary
stores/         # auth.ts, shop.ts (Pinia stores)
middleware/     # auth.ts (route protection)
supabase/       # database, functions, config
```

## Key Patterns
- Uses minimal theme (`themes/minimal.css`)
- Clean, professional styling with shadcn/ui variables
- Pinia for state management
- Supabase for backend (auth, database, functions)
- Stripe for payments
- Error boundaries for robustness

## Import Paths
- Shared UI: `@monorepo/ui`
- Local components: `~/components/[folder]/[Component].vue`
- Types: `~/types` (re-exports from shared)
- Utils: `~/utils`
- Stores: `~/stores/[store]`

## Authentication Flow
1. Google OAuth via Supabase
2. Protected routes with middleware
3. User data in auth store
4. Session management

## Payment Flow
1. Select coin package
2. Create Stripe checkout session
3. Redirect to Stripe
4. Handle webhook for completion
5. Update user coin balance

## Database Tables
- users (profiles)
- transactions (payment records)
- coin_balances (user holdings)
- coin_packages (available packages)

## Common Classes (Minimal Theme)
- `.bg-background`, `.bg-card` - Standard backgrounds
- `.text-foreground`, `.text-muted-foreground` - Text colors
- `.border-border` - Consistent borders
- `.bg-primary`, `.text-primary-foreground` - Buttons

## When Creating Components
1. Use minimal theme classes (shadcn/ui)
2. Add proper error handling
3. Use TypeScript types from shared package
4. Follow authentication patterns
5. Include loading states
6. Handle edge cases gracefully
